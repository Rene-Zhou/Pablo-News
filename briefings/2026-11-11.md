### 2. 🔥 Google DeepMind《AlphaProof Code》：AI agent 集群四周内对 Signal 协议的真实实现代码完成形式化验证——生成超 600 万行 Lean 证明，把"编译后运行在设备上的代码满足关键安全属性"证到数学层面；DeepMind 称这是**任何方法（无论是否用 AI）首次形式化验证一个广泛部署的加密协议实现**，Signal CTO 长文背书（HN 517 分、165 条评论）

DeepMind 11/10 发布的这项工作直接瞄准了形式化验证领域"长期被视为重大挑战"的目标：不是验证协议设计，而是验证**实际部署的代码**——Signal 协议保护着 Signal 与 Google Messages 里数十亿私人对话。AlphaProof Code 是一个多 LLM agent 框架，按研究团队的方式分工：人类专家与 AI 协作决定"证什么"（把 Signal 的安全目标翻译成形式化规约，人类逐条审阅），一组由 Gemini Carbon 驱动的 agent 负责"怎么证"——生成超 600 万行 Lean；随后 agent 审计证明并标出需要人类复核的区域，**只占代码库的 1%**。整个验证过程仅四周——历史上专家团队做同类工作需要数年。为确认系统能分辨正确与有缺陷的代码，团队把两个真实存在、此前已修复的 bug 重新注入隔离版 Signal 代码，两次都得到了"有缺陷版本不安全"的机器检查证明。

**关键细节：**
- 为什么难：此前的协议验证大多止步于设计层，而真实世界的漏洞往往藏在"设计—实现"的缝隙里；AlphaProof 证明的是编译后代码在设备被临时攻破前后仍保护消息等关键属性—— bridging 这个 gap 使证明复杂度大增
- Signal CTO Ehren Kret 的声明全文可读："此前的形式化验证必然局限于较小范围，这一新方法实现了显著扩展……随着 AI 驱动的安全威胁增长，用自动定理证明严格验证 Signal 核心协议，让我们对代码兑现隐私承诺更有信心"
- 展望部分点名了配套防御 agent CodeMender，并把下一步指向医疗设备固件与电网软件；技术论文在 google-deepmind.github.io/code-verification
- HN 评论区的三个方向：p-e-w——"Signal 的代码库不仅在实践意义上安全，甚至在严格形式意义上安全，写这些代码的工程师必是最高水平"；nurumaik 的许愿（"求求接下来验证 Telegram，一劳永逸解决'Telegram 不该自造密码学'之争"）；fercircularbuf 的转向——"去年我还担心大家把工作甩给 AI 后软件会变多 bug，这类工具让我觉得软件的未来可能反而更安全"

### 3. 🔥 Amazon 用 Strands Decider 决策模型替换工单分类里的 Claude Sonnet 4.6：每百万工单成本从 22,200 美元降到约 500 美元（98% 降幅）、单次调用从 4,215ms 到 897ms、年省数百万美元 token 成本——两位 Amazon 工程师的第一人称复盘显示"决策模型+小模型"正在吃掉 LLM 的分类类负载（HN 660 分、231 条评论）

Strands Agents 官方博客发布的案例来自 Amazon 内部全球最大规模工单系统之一：客户升级、容量请求、自动告警、安全发现等所有工单需归入 20 个类别。此前 Claude Sonnet 4.6（Bedrock）每张工单带长系统提示词生成 JSON 与推理，"九个月大的模型表现不错"；两位工程师（Carr Onstott、Mehul Jaiswal）换成一个月前发布的 Strands Decider——决策模型不生成文本，给定状态与选项集后返回每个选项的概率加置信度：状态即工单、选项即标签目录。实测对比：平均单次调用 4,215ms→897ms（-78%），每工单 token 6,724→2,010（-70%，其中输出从 170 token 到 1 个——就是那个选择），**每工单成本 $0.0222→约 $0.0005，每百万工单 $22,200→约 $500**；切流当天 Lambda 平均执行时长下降 74%。工程细节同样扎实：生产环境标签描述本身就超过 Decider 4,096-token 窗口，团队把 20 个标签各改写成一两句话作为选项；跑在 SageMaker ml.g5.xlarge（单张 A10G）上、模型占 19 GiB、单请求约 640ms、网络隔离；AppConfig 三档开关（BEDROCK/DUAL/DECIDER）实现灰度对跑。

**关键细节：**
- 先跑 Strands Decider 2B，测试集上 E4B（Gemma 4 构建）明显更好后切换；调优"置信度阈值达标才打标"后，E4B 在独立工单集上胜过生产环境的 Sonnet
- HN 评论区的"循环史观"高赞不断：armcat——"六年前我们用 SVM 建工单分类管线，几分钟训练、几毫秒分类；看着这个领域先扑向 LLM、又回到更快更便宜的分类器，很迷人"；phillennium 的三段论版本："造高效分类器"→"别管分类器了，造 machine god"→"machine god 太贵又平庸，还是造高效分类器吧"
- Kaedon 的算术核对：按每百万工单省约 2.17 万美元，年省数百万意味着年工单量至少 9,000 万张——"考虑到告警、安全发现、容量请求都走这个系统，规模可信，但依然惊人"
- 冷水与正名并存：oofbey 的抬杠（"成本降 98% 还只省'几百万'，说明原来的账单也就一亿多"）被 Kaedon 的规模核算部分化解；tdhz77 等人则指出这是"决策模型"品类的最佳广告位
- 连续性：与 Muse Ember（11-10 第 5 条）、Flide（11-10 第 8 条）拼成本周推理经济学的完整拼图——前沿实验室在小模型成本前沿贴身肉搏的同时，"分类/路由/打标"这类 LLM 误用负载正在被决策模型成建制回收；Strands（AWS 开源 agent 框架）借自家内部案例做品类教育，是决策模型从 Show HN 走进大厂生产栈的标志事件

### 5. e-means：Meta FAIR 用现代优化重写 k-means——epoch 数降一个数量级同时 loss 更低，GPU 端到端比 SOTA Lloyd 实现（Flash-KMeans）快 10–45 倍、CPU 上比 Faiss 快 8–15 倍，已并入 faiss 主库；作者阵容含 Hugo Touvron 与 Matthijs Douze（HN 491 分、76 条评论）

Swann Bessa 等（Mazaré、Szilvasy、Touvron、Picard、Douze、Jégou，arXiv 2611.09501）的发布页把卖点写成一句话："跨大规模数据集与多种规模，e-means 在 1.2–3 个 epoch 内达到 Lloyd 算法 25 个 epoch 的测试 loss 以下。"速度与质量在 k-means 里通常互为代价，e-means 两者兼得的关键是把 Lloyd 的全批更新换成按 scaling law 定步长的小步更新——交互演示里 Lloyd 每 epoch 仅 1 次更新，e-means 达 97 次，且更新规则保证质心始终留在凸包内。落地路径非常顺：代码已进 faiss/contrib（faiss 是全球最广泛使用的向量检索库），浏览器里即可试跑。

**关键细节：**
- 早期用户的复现已经出现：real_faxenoff 把方法适配到自己的 IVF 索引（code-daemon 项目），GPU 上拿到 146 倍加速
- 边界同样被社区标出：jlhawn 在"球面等面积网格松弛"的爱好项目里实测"确实不更好"——e-means 赢在减少对海量数据的遍数，没有数据集的场景（每次迭代即全部点）不适用；bashhq_r 提醒"超参数 scaling law 有事后拟合之嫌"
- shiandow 的理论视角获共鸣：这类算法往往能写成期望最大化或模拟退火的等价形式，e-means 或可理解为"带摩擦项的 EM"；wood_spirit 的朴素愿望是进 scipy——"比 faiss 离普通人的环境近得多"
- 连续性：与 Next-Concept Modeling（11-10 第 10 条）同属"经典算法被现代 ML 工具重做"的一周——一个是生成范式，一个是聚类基石；在推理经济学的大主题下，检索/聚类的每一点成本优化都会沿着 RAG 与向量数据库传导到每个 agent 的账单

### 12. Ginux：一个人 + 一个持久编码 agent，十一天造出能引导进入 Rocky Linux 10 用户态（systemd 到 multi-user.target）的独立 x86-64 内核——CIQ 创始人 Gregory Kurtzer 用 Zenodo 报告提出 HDAE（人类主导的 agent 工程）方法论；22,000 次浏览、2,200 次下载，作者自标"研究原型、未经安全审计、不主张生产可用"——⚠️ 本报补录：提交于 11/9 11:30 UTC，属 11-10 早报窗口内漏收，核对近三日早报全文从未见报后补入（HN 32 分、62 条评论）

Kurtzer（高性能容器运行时 Singularity/Apptainer 与 Warewulf 集群管理的作者、CIQ 创始人）把方法命名为 Human-Directed Agentic Engineering：人类定义架构、约束、里程碑、验收标准与停止点，自主循环负责实现、执行、诊断与修订。Ginux 作为实验对象：十一天、单个持久编码 agent 任务，产出 Rust 优先的 x86-64 内核——经 UEFI 引导、实现自己的核心 OS 机制与 Linux 兼容层、可执行部分未经修改的 Alpine Linux 程序、并引导 Rocky Linux 10 用户态（systemd 一路跑到 multi-user.target）。报告的克制同样构成信息：明确承认兼容与硬件覆盖面窄、无独立安全审计、"不主张生产就绪或与 Linux 等价"。

**关键细节：**
- HDAE 的核心主张与本周两条线呼应：Fable 5.2 集群形式化费马（11-10 第 1 条）证明"agent 集群+极少人工"的上限，Ginux 则给出"人类定义验收标准"这个可控中间态——不是全自动，也不是人写循环，而是人守里程碑、agent 守实现

### 16. Asahi Linux 全线从 MIT 切换到 GPL v2+：起因是"代码洗白"——攻击者从开发者个人 fork 里偷走未发布的特性代码，直接发布不署名、或经 LLM 重写抹掉出处，用于"取代该项目并激进地将 Apple Silicon 上的 Linux 商业化"；"LLM 让这一切变得便宜多了"——⚠️ 本报补录：提交于 11/9 03:06 UTC，属 11-10 早报窗口内漏收，核对近三日早报全文从未见报后补入（HN 73 分、38 条评论）

It's FOSS（Abhishek Prakash，11/8）报道：让 Apple Silicon Mac 能跑 Linux 的 Asahi Linux 宣布所有仓库迁移到 GPL v2 或更高版本——只走强 copyleft。多年以来该项目大部分自有代码采用 MIT（为了让包括 BSD 在内的各方自由复用）；改变的原因是他们受够了 code laundering：最恶劣的案例里，仍在开发中的特性代码被从开发者的个人 fork 里直接搬走——或者原样发布不署名，或者用 AI 重写以隐藏来源——目的都是绕过许可证义务、包装成自己的产品。文章对"洗白"的科普正是这条新闻的时代注脚：AI 之前要人工逐行重写、重命名变量、打乱函数；现在 LLM 把单次成本压到近零。

**关键细节：**
- 许可证选择的攻防重新成为工程议题：MIT 的宽容（保留版权声明即可）恰恰是此次被利用的口子；GPL 的传染性让"拿走改造闭源卖钱"面临法律暴露——开源项目第一次把 LLM 重写武器化纳入威胁模型来选许可证
- HN 讨论延伸到检测与举证：AI 重写后的代码还能否被证明衍生自原作，是 copyleft 执法在新现实下的核心难题
- 连续性：与 STE80 去 AI 味工具（11-10 页脚留观）、370 本书 AI 量产写作等同属"LLM 让洗白/量产变便宜"的伦理与治理面；Asahi 给出的回应是法律工具（换许可证）而非技术工具——开源社区对 AI 时代版权真空的第一批结构性适应正在开始
