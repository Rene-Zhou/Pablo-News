### 3. 🔥 Ruby2ßhell：一个 ß 字符打穿 Ruby——大小写转换单字节堆溢出直达 RCE，Rails/Sinatra 默认配置无需认证即可触达；Ruby 官方同日公告共七个漏洞（含正则 double-free），3.3.14/3.4.13/4.0.10 修复；GitLab 19.6.0 当天发版仍未修且零沟通——本周第三记"起名艺术"级 RCE（HN 346 分 + 官方公告 327 分）

Veria Labs 披露页（全文实读）+ Ruby 官方安全公告（全文实读）：GHSA-34m4-m9fh-gqp5（CVE 待定，Critical）。根因：多数单字节编码里没有"大写 ß"，上转换要写两字节 SS，但循环只做单字节边界检查（`to < to_end` 只保证一字节空间）；输出缓冲按输入长度+20 字节分配，21 个 ß 即溢出一字节。该循环存在于多个 ISO-8859/Windows-125x 编码、自 Ruby 2.4.0 起就在；`upcase`/`swapcase`/`downcase(:fold)`/`casecmp` 皆可达。可达面：**Rails 与 classic 风格 Sinatra 在默认配置下受影响**——网络可达、无需认证。Ruby 官方同日公告：共七个漏洞（另含正则编译 double-free GHSA-7x2q、case 转换整数溢出 GHSA-87fm、大小写不敏感正则 OOB 读 GHSA-wpqw 等），"已知有 PoC 证明其中数个可触发 RCE"，强烈建议立即升级 3.3.14/3.4.13/4.0.10（3.2 及更早已 EOL 无修复）。

**关键细节：**
- 受影响捆绑软件清单（Veria 表格）：GitLab 19.6.0（内嵌 Ruby 3.3.13，受影响）、GitHub Enterprise Server 3.22.5（4.0.9，受影响）、Chatwoot 4.20.0（3.4.4，受影响）；Mastodon/OpenProject/Discourse 基础镜像已修
- HN 的 GitLab 帖（20 分）补了最扎心的一刀：hoechst 实测 `gitlab-ee 19.6.0` 的包仓库里 Ruby 仍带洞、内嵌 nginx 1.31.7 亦未修 NGINX2Root——"常规月度版照发、安全公告只字未提、老版本补丁不存在"——自家渲染栈里两枚本周 RCE 全中
- cowlevel 的评论把本周连成了趋势线："最近的 RCE 浪潮，是人们找到单字节溢出后、用 AI 补完利用链剩下的苦活——如果任何单字节溢出都能低成本转成 RCE，那我们除了把整个软件栈做成内存安全别无选择"（AI 同时降低攻防两侧的成本，见第 12 条逆向工作流）
- 命名梗的胜利：社区对 "Ruby2ßhell"（ß 双关 Shell/ ß→SS）好评如潮——lousken："Scheiße2Shell？"；tvvocold："One Shell a Day, Ops Run Away"
- 连续性：本报 RCE 周第三拍——Java4Shell（11-19 第 3 条）→NGINX 双 RCE（11-19 第 4 条）→**Ruby2ßshell + Ruby 七连洞**；Java4Shell 还有续集：HN 帖（263 分）发现 OpenJDK 的 GitHub PR #32781（9 月 9 日，"AVX-512 Base64 decoder overwrites output buffer on short padded tail"）正是该洞的修复提交——漏洞在披露前两个多月就修了，只是没人把它当 RCE 看

### 5. PostgreSQL 19 发布：REPACK (CONCURRENTLY) 让表优化不再锁表、pg_plan_advice 稳住查询计划、standby "read-your-writes" 一致性上线——30 年开源数据库的又一次"关键负载"升级（HN 65 分）

PostgreSQL 全球开发组（11-19，全文实读）：PG19 主打"关键负载的规模化运维"。核心三项：①`REPACK (CONCURRENTLY)`——回收膨胀空间、按索引重排数据且不阻塞读写，接替 VACUUM FULL/CLUSTER 的重负载场景（两者保留兼容）；②`pg_plan_advice` 扩展——数据变化导致计划翻车时锁定计划稳定性；③standby 支持"read-your-writes"一致性 + "get or create"省一次网络往返。核心团队 Jonathan Katz："30 年来全球社区把它建成了组织敢托付关键数据的数据库。"

**关键细节：**
- REPACK 是本版头条：以往 VACUUM FULL 要独占锁表，高写入业务只能挑停机窗口；CONCURRENTLY 版本把"在线重组"变成常规运维动作——对 AI 应用普遍的"向量+业务混部"PG 集群是实打实的运维减负
- 与本周 Ruby/NGINX 安全风暴的对照：PG19 同日发布并无安全通告噪音，HN 65 分的平静分数恰是"基础设施无聊即美德"的注脚
- 连续性：与昨日 Cerebras 分离式推理（11-19 第 11 条）同属"AI 时代的存储与算力底盘"议题——推理要快，数据库也不能锁表

### 6. "去你的 AI 安全护栏"：开发者修自家产品的安全漏洞被 Claude 拦下——豁免流程要交护照、等数个工作日、放弃数据保留权利；作者最后用 EU 托管的 GLM 5.3 完成整个修复，"罪犯从来不用申请批准"（HN 282 分、103 条评论）

爱沙尼亚资深工程师 ounapuu 的博客（全文实读）：给自家项目跑 Claude Code 做安全加固，找到一个一行修复的低垂果实，随即被"AI safeguards"拦停。豁免申请的现实：数个工作日等待、放弃数据保留豁免（"但愿你没有 IP 要保护"）、上传政府身份证件或护照（"我们保证不泄露"）、且"可能照样不批"。作者的结论与替代路径：改用 EU 托管的开放权重模型 GLM 5.3，完整走完"证明漏洞存在→修复→验证闭环"——"恭喜 Anthropic，你们让世界更不安全了。或者这正是你们 IPO 前拉监管护城河的计划。"

**关键细节：**
- 核心论点的归谬：安全护栏挡住的正是"想让自己服务更安全的人"——恶意者直接用 abliterated 开源权重或无护栏模型；"刀可以切菜也可以伤人，但买刀不需要交身份证申请"
- 时间点让这条博客的传播翻倍：发于 ANT 上市当日，"IPO 前的护城河"指控与街头的反 AI 泡沫抗议（TechPolicy Press：抗议者喊"别给 AI 泡沫救市"，HN 16 分）形成呼应

### 13. PTP：黑盒"逆语言模型"实现近精确 prompt 重建——只用目标 LLM 自己的合成数据从零训练逆模型，previous-token prediction 反着学；系统提示与敏感输入的保密性再受冲击（HN 46 分）

arXiv 2607.29378（全文实读）：现有 LLM 反演走"语义重建"路线（微调 seq2seq、需要权重或 logits 访问）。PTP（Previous-Token Prediction）改为功能性反演：完全黑盒、从头训练一个显式逆语言模型，训练数据全部由目标 LLM 自身合成生成；类比前向的 next-token prediction，逆模型学习 previous-token prediction，实现近精确（near-exact）的 prompt 重建。

**关键细节：**
- 与语义重建的差异是关键卖点：不追求"意思接近"、追求逐 token 近精确复原——对"系统提示防爬""企业 prompt 含敏感数据"的场景是更硬的威胁模型
- 黑盒 + 纯合成数据意味着门槛极低：不需要模型权重、不需要 logits、不需要大规模外部数据集，只要能调 API 就能训练逆模型
