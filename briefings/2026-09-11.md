### 1. 🔥 DeepSeek 开源 V4.1 Flash：552B 多模态 MoE，百万 token 上下文，MIT 协议

**DeepSeek 9 月 10 日发布 V4.1 Flash——多模态 MoE 模型：552B 总参数量，原生同时处理图像与文本，支持最长 100 万 token 上下文，开放权重 + MIT 协议上线 Hugging Face，以 883 分、495 条评论登顶当日 HN。** 模型主打长输入场景的成本效率：预填充阶段每 token 仅激活 8B 参数、解码阶段激活 16B，官方定位是面向"输入密集型 agent 工作负载"的推理优化。

**关键细节：**
- 架构：采用全新 Causal Encoder-Decoder（CED）——40 层 Transformer 拆成 20 层因果编码器 + 20 层解码器，解码器全局 KV cache 由编码器最终隐状态投影而来，而非逐层自建；配套 SWA Bounded Replay 只需回放最近窗口 token 即可重建缺失的 SWA KV 状态，避免持久化 KV cache 落盘
- 发布即附技术报告 PDF 与推理端点，Hugging Face 上线数小时获 1254 赞，被社区视为"KV cache 压缩极限"方向的里程碑
- HN 讨论（495 条）焦点：百万上下文 + 8B 活跃参数的性价比，以及 CED 架构对 agent 型负载推理成本的实际影响

### 2. 🔥 OpenAI 数学成果信任危机升级：第二位数学家公开指控"不诚实"，要求训练数据溯源证明

**继 9/9 早报 Navier-Stokes 之争后，数学家 Andreas Thom 在 Mathstodon 公开质疑：他与同事与 ChatGPT 的交互可能在 OpenAI 的训练数据中，并因此"贡献"了公司 8 月高调宣布的数学成果之一；在致信 OpenAI 研究人员未获满意答复后，他写道"至少在我看来，这是不诚实（dishonesty）"。（370 分帖 + The Verge 71 分报道 + 254 分 Bluesky 跟进）** The Verge 报道：OpenAI 上月宣布的 10 项数学突破中，涉及 Thom 所在领域的"non-sofic groups"结果被官方承认大量建立在 Thom 与 Gábor Kun 的先前工作之上——该成果最初因未致谢而遭数学界批评，OpenAI 事后悄悄修改了声明。

**关键细节：**
- Thom 的疑虑：他称被"OpenAI 对我们技术的精细掌握"震动——所用方法在当时"既非最显然、也非最有希望的路线"；他致信 OpenAI 的 Sébastien Bubeck 与哈佛统计学家 Mark Sellke，询问其 ChatGPT 对话是否"属于训练数据或可被推理过程访问"
- 答复不令人满意：Thom 称对方只回应了"对话能否被直接访问"，回避了是否已进入训练数据池的问题——"没有任何限定、解释或证据"
- 学界与社区跟进：研究员 Tim Kellogg 在 Bluesky 发帖（254 分）认为相关工作"很可能是模型训练的候选数据"，呼吁 OpenAI 建立更好的数据来源档案（data provenance）；也有评论反驳"选择加入改进模型即同意"未必构成学术伦理上的知情同意
- 连续叙事：这是继 NYU 教授 Buckmaster 指控 OpenAI"抢跑"其未公开成果后，第二位公开质疑的研究者——学界对"OpenAI 是否用用户对话训练出数学突破"的信任正在系统性瓦解，HN 热评称"OpenAI 需要更好数据溯源来对抗指控"

### 4. Cognition 发布 SWE-2：以 Kimi K3 为基座的编码模型，FrontierCode 50.0%，比 Fable 5.1 便宜 64%

**Cognition 9 月 10 日发布 SWE-2——其最强编码模型：在 FrontierCode 1.1 Main 上达到 50.0%（距 Fable 5.1 仅 1 分内），而成本低 64%；官方称首次将 RL 扩展到"数万亿参数"规模，在单次训练中同时推进所有推理强度档位的能力-成本前沿。** SWE-2 基于 Moonshot Kimi K3（2.8T 参数）后训练，在多个编码基准上同时击败自家 SWE-1.7 与 Grok 4.6。

**关键细节：**
- 基准表现：FrontierCode 1.1 Main 50.0%（Kimi K3 44.2% / Grok 4.6 48.0% / Fable 5.1 50.9% / GPT-6 Astra 53.3%）；DeepSWE 1.1 达 73.0%；Terminal-Bench 2.1 达 92.8%
- 训练方法：按强度档位施加线性成本惩罚的单一 RL 运行（每档惩罚按基座模型帕累托前沿的局部斜率调参）；沿用长度加权奖励基线稳定训练；用在线 draft 模型 + NVFP4/FP8 核 + 量化感知训练压低显存
- 数据工程：RL 环境数量翻三倍，新增指令跟随覆盖层，并用此前 SWE-2 检查点构建数据飞轮
- 定位：在"接近 GPT-6 Astra 水平（差距几个点）但仅需其四分之一成本"的区间与全能模型竞争

### 5. 3.8B 模型训练到 0.384 CORE 只要 998 美元：8×B200、43 小时的"低成本训练"路线图

**Hugo Vergnes 展示了一条惊人的性价比训练路线：基于 2048 上下文、3.848B 参数的 little-lm，在 8× B200 上训练 65.3B token、耗时 43 小时、总成本 998 美元，达到 0.384 CORE 基准分——显著超过 GPT-2（1.5B，0.2565 CORE）。** 训练数据 57.3B token 的 1024 上下文版本更是只需 820 美元（35.9 小时）。

**关键细节：**
- 对照：nanochat d26（~561M，11.2B token，8×H100，约 3 小时）约 0.258 CORE——little-lm 以更高参数量拿到了明显更高的分数
- 含义：当"小模型 + 足够高质量数据"能逼近 frontline 模型基线时，训练经济学正在下探到千美元级，个人研究者与小型团队可以负担
- HN 讨论（18 条）焦点：CORE 基准的可信度、数据配比与 B200 集群获取成本

### 8. Meta 的"AI 三人小组"实验复盘：代码变更 +220%，真正交付的功能只涨 36%，事故却升了 40%

**LeadDev 复盘 Meta 年初的"pods"试验：把 10-20 人的产品团队砍成 3-5 人 + AI 工具/代理的小组，结果是内部平台代码变更同比 +220%，但真正抵达用户的新功能只涨 36%，重大技术/安全事故 +40%、员工救火时间 +70%——"AI 让开发者产出更多，未必让组织产出更多有用的东西"。** 该实验此前经 Reuters 调查报道（8/26："扎克伯格用 AI 替换员工的宏大计划如何崩掉"）。

**关键细节：**
- 更大样本：500+ 组织的数据显示 PR 吞吐量提升 37%，但开发者体验反而下降；DX 的 Brian Houck 直言"我们太爱输出数字，不够关注结果指标"
- 结论共识：合理规模的小组应是 5-8 人而非更小；收缩团队应当是最后手段而非第一步
- 行业回响：HN 讨论（仅 4 条评论但话题热）与工程管理社区普遍引为"AI 原生团队"组织设计的反面教材

### 9. 论文：LLM 会通过对环境的"自适应探索"自发发展出全新社会偏见——哪怕分组之间没有任何固有差异

**一篇 ICLR 投稿论文（200 分、116 条评论登上 HN）让 LLM 扮演虚构城市 Toma City（约 10 万居民、来自四个始祖村庄 Tufa/Aima/Reku/Weki）的招聘顾问，为医生、律师、保姆、清洁工等二十个岗位筛选候选人——结果模型自发地对"人工构造的、不存在任何固有差异的人口分组"发展出了新的社会偏见。** 作者称这证明偏见机制内嵌于模型的决策流程：偏见不需要来自训练数据的统计相关性，也能在对环境的自适应探索中涌现。

**关键细节：**
- 实验设计：分组是纯粹的虚构标签，组间没有任何真实差异；模型在逐轮"探索—反馈"中学会对某些组别系统性倾斜
- HN 讨论（116 条）焦点：批评者认为城市/岗位设定本身携带隐性提示（"让 LLM 做决策本身就是错误问题"），支持者则强调"无固有差异却涌现偏见"的机制性结论
- 现实含义：当 LLM 被接入真实决策框架（招聘、贷款、执法），偏见可能不是"复读训练数据"，而是决策过程中实时生成的新问题
