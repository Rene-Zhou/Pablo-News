### 7. NVIDIA 开源 OpenShell：给"自主 agent 舰队"造的安全运行时——内核级策略执行 + 形式化验证策略变更，"agent 永远看不到真实凭证"（HN 144 分）

**NVIDIA 以 Apache-2.0 开源 OpenShell（已上 PyPI）：自主 AI agent 舰队的安全、私有运行时。双保险设计：其一，内核级执行——每个 agent 跑在隔离沙箱里，内核管控它能访问哪些文件、调用哪些系统调用，每次网络连接出沙箱前都要过策略检查；agent 永远见不到真实凭证，OpenShell 只对"发往已批准端点的请求"按需注入。其二，形式化验证策略变更——新策略生效前先形式化检查它将授予的危险新访问（带着凭证连新主机、调用新 API 方法），命中即挂起等人审。**

**关键细节：**
- HN 第一反应是命名反差：vermaden——"Open 和 Nvidia 出现在同一句话里，是个漂亮的矛盾修辞"；overflowy 则翻出文档细节：默认开启匿名遥测（可设 OPENSHELL_TELEMETRY_ENABLED=false 关闭）
- crypt1d 的亲历更有意思：上周末想 vibe code 一个类似工具，被 Claude 的安全分类器拦住——"连做进程执行的审计跟踪都不行，自定义内核 hook 不让、现成软件也不让"——防御方模型的护栏与防御方基建的需求迎头相撞
- mfro 的冷水与认可并存："还没把 agent 关进容器的，纯属疯了。不过这看着是管理那些容器的好办法"
- 连续性：与昨日 LayerFS（agent 文件系统）、GitHub agent-scale Git、Alter（多用户 agent 权限控制）同周出现——"agent 时代的操作系统原语"正在快速分层成型；Railway 事件（第 3 条）恰好解释了它的必要性：托管平台的环境变量一旦泄露就是全军覆没，OpenShell 的答案是让凭证根本不进入 agent 执行域
