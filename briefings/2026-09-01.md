### 1. 🔥 安全研究者攻破 Claude Code "Auto Mode"：一个网页摘要请求即可劫持 Opus 5，代码执行成功率 60-80%

**Embrace The Red（wunderwuzzi）发布研究：向处于 Auto Mode 的 Claude Code Opus 5 提交简单的"网页内容摘要"请求，即可触发提示注入并劫持代理，实现代码执行——小样本测试中攻击成功率达 60-80%。** 这直接打脸 Anthropic 委托第三方（Trajectory Labs）得出的"Opus 5 Auto Mode 提示注入攻击成功率 0.00%"评估结论。文章以 310 分、104 条评论成为今日 HN 热度最高的 AI 安全新闻。

**关键细节：**
- 背景：Auto Mode 自 8 月中旬起已成为 Claude Code 的默认启动模式——用安全分类器取代人类审批弹窗，"无人工确认即可执行操作"
- 攻击路径：研究者仅让代理"总结某个网站的内容"，页面内嵌的恶意指令即完成了对会话的劫持与代码执行，无需用户批准
- 与官方口径的矛盾：Anthropic 的 Boris Cherny 此前发文称分层防御（模型训练 + 输入探针 + 意图分类器）可把未见攻击的间接提示注入成功率压到"接近零"——研究者用 60-80% 的实际成功率回应"蛇油销售员式的误导"
- HN 讨论焦点：社区担忧"默认开启 Auto Mode + 营销口径低估风险"的组合正在把安全负担转嫁给普通用户，评论直呼"一旦出现损害，这配置就是集体诉讼的素材"
- 连续叙事：与 8/31 早报 Claude Code 会话 URL 写入 commit 的争议同属"Anthropic 开发者工具默认行为"安全线——Auto Mode 是比"默认行为"更进一步的"默认授权"

### 2. 🔥 Simon Willison 万字拆解 "ChatGPT Work"：其实是"云端 Work + 本地 Work"两个产品，能力远超 ChatGPT Chat

**OpenAI 于 7 月 9 日发布的 ChatGPT Work 一直被外界视为"换了皮的 ChatGPT"。Simon Willison 在 8 月 30 日的长篇分析中给出结论：Work 实际上是两个产品——运行在云端的 Work Cloud（chatgpt.com 与移动端）和运行在桌面应用（前 Codex）里的 Work Local，后者"更像是把 Codex 重装修，让非程序员不害怕"。** 文章以 307 分、172 条评论登顶 HN 开发者视角新闻，配套的"ChatGPT Work 工具与技能参考"手册另获 144 分。

**关键细节：**
- 门槛：两种 Work 都仅限 $20/月及以上订阅者——免费用户和 $8/月的 Go 用户无权访问
- Work 与 Chat 的本质区别：OpenAI 官方口径是"Chat 用于要答案，Work 用于要交付物（简报、PPT、分析、工作流）"——Willison 直言"这等于没说"，因为他多年一直用 Chat 干这些事
- Work 独有能力清单：可选 Luna/Terra 替代 Sol 模型；带联网的代码执行环境；无头 Chrome 浏览器；跨会话持久文件系统；发布 ChatGPT Sites；用 Sol/Luna/Terra 跑子代理会话；定时 prompt 自动化；推理档位 Light→Ultra 可选
- 计费细节：Work 会话按 Codex 额度计费，Chat 会话有独立额度——"混乱但强力的产品"是 Willison 的总结

### 6. "Agent 记忆应该是一种文件格式"：Memoryfields 作者痛批三类主流记忆方案

**Cal Paterson 发表《Agent memory as a file format》：主流 Agent 记忆系统"各有各的烂法"，真正的方案是把记忆做成文件——像文件系统一样可读、可查、可被任何工具处理。** 文章以 144 分、75 条评论登上 HN，成为"Agent 记忆该怎么做"的最新争论焦点（与 8/31 早报 Lemmalog 的 Datalog 方案形成对照）。

**关键细节：**
- 前提：真实 Agent 不应从空白上下文启动——"你的 Agent 应该带着记忆开始工作"，而基准测试从空上下文开始是为了公平，但偏离了现实
- 三类失败方案：(1) 锁死绑定特定厂商 harness 的记忆系统——本质是实验室想从"API 生意"转型"平台生意"，挖掘对话历史的结果是"记忆全关于你"而非关于世界；(2) 复杂到荒谬的系统——一个知名方案要 pgvector + Neo4j 图库 + 一个专属 LLM 来决定什么值得记；(3) "高级现代主义"方案——理想化的图/逻辑命题记忆，把信息从上下文中剥离到"对 Agent 毫无意义"
- 主张：记忆用文件格式承载（如 memoryfields），配合简单的目录结构与工具链即可，无需数据库
- HN 讨论：与"符号系统 + LLM 混合"（Lemmalog）、向量库派形成三方路线之争——"记忆问题"正在成为 Agent 架构的下一个主战场

### 9. 扩散语言模型复兴：Kuleshov 组发布"从零构建扩散 LM"教程，DeepMind 研究员复盘连续扩散回归

**两篇扩散语言模型内容同日占据 HN：(1) 康奈尔 Kuleshov 组发布《How to Build a Diffusion Language Model》长教程（167 分）——从掩码扩散讲起，覆盖迭代精化、后训练与变长生成，素材改编自 ICLR 2026 与 MLSS 2026 讲座；(2) DeepMind 研究员 Sander Dieleman 发布《Continuous diffusion language models》（127 分）——长达 44 分钟阅读量的综述，指出连续扩散语言建模"在沉寂数年后正在回归"。**

**关键细节：**
- 教程主线：先讲自回归 vs 扩散范式差异，再逐步构建"真实世界的扩散 LLM"——块扩散（block diffusion）解决变长生成、迭代精化自带纠错能力、蒸馏加速采样、可控生成
- Dieleman 的观察：完全离散扩散一度取代了早年的连续扩散尝试，但近期研究激增表明"潮水转向"——连续扩散在语言上卷土重来，主要因为其在推理加速、可控性与缩放规律上的新进展
- 意义：扩散 LLM 被视为"自回归之外的第二条缩放路径"——若连续扩散在语言上追上离散方法，推理成本结构可能再次改变（与 GLM-5.3-Flash 的线性注意力叙事同属"非自回归"谱系）

### 12. Instagram 收紧"AI 生成人物"账号：未披露的 AI 账号将被限流

**Instagram 8 月 31 日宣布调整 AI 生成账号的标识政策：将原有的"AI 创作者（AI creator）"标签更名为"AI 生成账号（AI-generated profile）"，并开始限制"展示 AI 生成人物却不披露"的账号的触达。** 官方称此举回应了大量用户"以为关注的是真人、事后才发现是 AI"的投诉。

**关键细节：**
- 规则边界：正确打标的使用者不会仅因"账号主体是 AI 生成人物"受罚；用 AI 修图、润色文案、做配图等常规创作不需要打该标签
- 触发背景：Wired 调查发现同性交友 App Goose 背后有 20+ 个疑似 AI 网红账号主动私信拉新；NYT 7 月报道数百个"AI 医生/养生博主"在社媒推销保健品——AI 网红的欺骗性问题持续发酵
- 平台连坐：上周 Meta 刚与多州达成 180 亿美元和解（青少年保护），此前又因"AI 生成他人形象"工具遭抵制而下线该功能——内容平台正在 AI 治理上密集补课
- 与 FTC/欧盟对"AI 披露"的强制要求同频：社媒平台的 AI 标识义务正从"自律"走向"规则化"
