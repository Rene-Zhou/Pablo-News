### 2. 🔥 Claude Code 被曝定期把每个后台 agent 的完整转写发给模型——只为生成一个约 3 个词的状态行，gist 实测烧掉 15–20% token；有 Max 订阅者对账一周隐性花费约 380 美元（占 16%）；后续实测称"影响约 8%、多为缓存读"——但疑似 Anthropic 已悄悄调整（HN 553 分、220 条评论）

**flamerix-ai 的 gist（173 星、11 fork）《Claude Code burns ~15-20% of your tokens on a 3-word status line》：Claude Code 会定期把每个后台（子）agent 的完整 transcript 发给模型生成 agent_summary 状态标签——每 30 秒一次，换来界面上一行约 3 个词的状态。作者提供的补丁是一个 Bun preload 脚本：全局劫持 setTimeout、识别并丢弃这类调用。**

**关键细节：**
- simon83 的对账最具体：20x Max 计划、周配额用到 98%，让 Opus 分析自己的 transcript 后按 30 秒定时器估算——本周 API 等价花费 $1,970，其中隐藏的状态标签调用约 $380、占比 16%，"这难以置信"
- 疑似官方热修：gym——"两天前，用满 5 小时窗口的 100% 会吃掉周配额的 25%；今天同样操作只占 13%，有什么东西被修好了"
- jakozaur 的复核："真实但有细节——只影响 subagent，workflows（ultracode）似乎不受影响；且大部分是缓存读，短上下文子 agent 成本很小；我的会话里大约最多 8%"
- HeavenFox 的疑问代表另一面："既然发的是完整 transcript，难道不几乎全是缓存命中、因此相当便宜？"——与 jakozaur 的"长上下文子 agent 才贵"互为注脚
- 评论区的制度建设：dozerly——"这就是 harness 的职责。推理提供商自己下场做 harness，激励天生不对齐"；franticgecko3——"'Claude Code 无缘无故烧大量 token'的标题我们已经见过不止一次，是时候质疑模型提供商亲自发 harness 的动机了"
- 补丁本身评价两极：aidos 赞"全局 setTimeout 补丁可怕又巧妙，真正的黑客精神还在，我批准"；jon-wood 则反讽 gist 本身"纯粹是 Claude 腔——无穷无尽的跑题废话，把一个简单补丁埋进没必要的年表、版本表和对动机的幻觉式猜测里"——一篇关于 LLM 腔的文档自己长成了 LLM 腔，与今日第 9 条 Martin Fowler 同日对读
- 彩蛋（AlexErrant）：Anthropic 会把你的邮箱放进系统提示、Opus 持续把它带在请求头里，社区已有插件可移除

### 4. Alpine Linux 披露 GitLab CVE-2026-97229 在野利用未遂："攻击差点成功"——实例按被攻破处理、从零重建；最阴的细节：升级到 GitLab 19.3.6 并不能修复，因为补丁打在 GitLab 自带的 Ruby 里，Alpine 的镜像用的是标准 Ruby（HN 241 分、119 条评论）

**Alpine 官方复盘（10/28）：10/20–21 有攻击者在其 GitLab 实例上尝试利用 CVE-2026-97229（CVSS 10.0，GitLab CI 配置中正则表达式求值漏洞，根源在 Ruby 正则引擎 Onigmo 的整数溢出）——距 GitLab 发布修复仅一周。"攻击接近成功。我们未找到它成功的证据，但不能排除"，因此实例按被攻破处理、从零重建，全部密码重置；核查显示 aports 仓库、软件包与 10/21 的发行版未被篡改。**

**关键细节：**
- 修复链条的断点（原文+JLO64 顶贴引述）：GitLab 10/12 发布修复版本，但修复方式是给自己包与容器镜像里捆绑的 Ruby 打补丁——Alpine 的镜像用标准 Ruby，"10/22 升级到 GitLab 19.3.6 没有修复漏洞"；上游 Ruby 直到 10/23 才发修复（3.3.13），含修复的新镜像 10/27 才重新发布
- 波及面警示（原文原话）："bug 在 Ruby 的正则引擎里，任何从不可信输入编译正则表达式的程序都暴露，不只是 GitLab"
- 评论区的建设性抬杠：akerseten——"重新发布修复过的 19.3.6 镜像而不打新版本号？10/27 之前拉的 19.3.6 全是带洞的，这不难坑死人"；rollulus 以 eMudhra 先例类比："Go 当时紧急发版拉黑证书、保护没跟上的依赖方，GitLab 是不是也该拉黑带洞的 Ruby 运行时？"
- cowlevel 的疲惫很有代表性："随机一个 C 数据处理库里的整数溢出导致 RCE——本周开始，谁还没看腻 C 库？"
- KronisLV 的立场："以安全为卖点的 Alpine 也许就不该跑 GitLab——攻击面太大，除非有专职团队只干这个。审计一遍 Forgejo 源码自建不好吗"；saidnooneever 则点赞处置："没有证据≠没发生，推倒重建，体面，脱帽致敬"
- 连续性：本报"补丁洪峰"线（PHP2Shell 10/22–25、GitLab CVSS 10 披露 10/23、CloudSleuth 补丁查询 10-28）——今日是该 CVE 首份"在野利用 + 修复链断点"公开案例；与昨日 Apple/eMudhra（信任链底层清理周期长、补丁被覆盖）同一个结构性教训：越靠近底层的缺陷，修复传播越依赖每一层中间商
