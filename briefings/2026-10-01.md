### 4. Launch HN：Magnitude（YC S25）——会给自己调参的代理推理引擎，比 llama.cpp 快最多 2 倍

**9/30 Launch HN（85 分、42 条评论）：YC S25 公司 Magnitude 开源代理专用推理引擎——内核在你的设备上现场编译与调优，官方称开放模型跑分最高比 llama.cpp 快 2 倍，Mac/Linux/Windows、Apple Silicon/NVIDIA/AMD/纯 CPU 通吃。**

**关键细节：**
- 切入点：现有引擎都要做取舍——vLLM/SGLang 为数据中心批量推理牺牲单会话性能，llama.cpp/Ollama 为兼容性放弃针对特定硬件优化，oMLX/ds4 又缺引擎完整性；且没有一款是为"本地跑代理"设计的
- 代理场景的特殊需求：会话很长、经常多个并行、还得留着算力正常用电脑
- 做法：内核带弹性参数、跑前在你这台机器上实测调优，"广硬件兼容 + 接近专用内核的性能上限"；只给最流行的开放权重家族写高优化内核
- 基准坦白：引用的是 Moby Dick 散文复读任务（64K 上下文），创始人承认"llama.cpp 配置不同方差很大，也想看对 MLX 的对比"
- 商业模式：未来做混合负载推理云，"消费级硬件本地跑日常、难题上云无缝切换"
- 团队背景：两位创始人此前的开源浏览器代理拿到 4k+ star、10 万+ 下载

### 5. Pi 官宣支持 MCP：《You Said No MCP!》——"我们为什么改主意"的 RFC 式复盘（540 分）

**9/29 Earendil 团队（Flask 作者 Armin Ronacher 一方）发布 RFC 式长文（540 分、314 条评论，为窗口期全站第二热）：曾把"Pi 不支持 MCP"挂在官网首页的团队，正式把 MCP 纳入核心——并坦承播客里diss过 MCP 不止一次。**

**关键细节：**
- 改口的三个理由：今天的 MCP 已不是去年的 MCP；给 MCP 做支撑所需的改动（沙箱解释器）对 Pi 本身"普遍有用"，还顺带让 Jev 在 Pi 里更好用；"影响一件事的最好方式是参与进去，而不是站在场边看"
- 核心洞察："Pi 需要的东西和 MCP 需要的东西本质相同——一个可以玩耍的沙箱（解释器）"
- 仍然不变的批评：MCP 最大的问题始终是难以组合（compose）；很多 MCP 服务器还是为"把工具一股脑倒进上下文、靠文本省 token"的旧 harness 优化——团队的主张是"MCP 应该更接近带智能工具发现的 OpenAPI：返回结构化数据、靠文档可被发现"
- Codemode 概念：跑在 harness 受信侧的 JavaScript 沙箱，让代理用 JS 编排组合工具调用，状态存在会话转录而非文件系统；JS 可以 WASM 小体积分发
- HN 论战：经典梗"MCP 是 NIH 版 OpenAPI"；也有人辩护"就像 API 但自带文档"；作者本人在评论区亲自下场："不建议去读我们 clanker 改的 PR 来理解它——那是衍生物的衍生物"

### 6. 16 岁研究者用自研 AI Hackbot 找到微软漏捅：一个不验签的 JWT，17 万亿行内部数据近在咫尺

**9/25 发布、HN 197 分（89 条评论）：16 岁安全研究员 Faav 披露微软内部分析服务 Titan 的严重漏洞——/v2/Query 接口接受原始 SQL 却不校验 JWT 签名，17 万亿行记录理论上触手可及；最初的线索来自他自建的 AI 漏洞猎手 Antares。**

**关键细节：**
- 攻击链：Antares 8 月 25 日从微软子域名扫描中锁定 Titan；前端有 VPN 墙但独立 API 端点的公开 Swagger 文件暴露 4 条路由，其中只有 /v2/Query 免 Azure AD 鉴权、且吃原生 SQL
- 验签形同虚设的过程堪称行为艺术：改 tenant → 报租户错误；改 audience → 报受众错误；改应用 ID → 报白名单错误；改到用户查找——"payload 一直在变、签名纹丝不动，Titan 照单全收，像门卫只核对身份证上的名字却从不看照片"
- 表名从哪来：从 Wayback Machine 的 2023 年 Titan 页面快照里读出的旧 Superset 配置，恢复出 56 个表定义
- 分寸与回报：全部影响均为假设性验证（SELECT 1），未触碰任何客户数据/PII；微软致谢并加固服务，赏金 $5,000——HN 讨论："漏洞定价本质上是'国家级攻击者能否无感利用'的代理指标"
- AI 角度：作者自述"把 AI 融进挖洞流程"才有了 Antares，这条线从自动线索开始、十天后由人类的深夜直觉收尾——与此前"AI 安全研究员"叙事互为镜像：同一代模型，一边被防御者用来找洞，一边被攻击者用来找你

### 10. PostHog 开源 Jeeves：让 Jev 式决策模型"先想后判"——9B 模型在域外测试反超 Jev

**9/29 PostHog 发布（HN 239 分、93 条评论）：Jeeves 是一个会推理的 Jev 式分类器——基于 Qwen3.5-9B（LoRA + 指针头）加大块-4 扩散草稿器，用 SFT + CISPO 训练，MIT 协议开源权重。**

- 成绩单：从未训练过的测试集上整体准确率 0.889（Kev-9B 为 0.822、Jev 为 0.857）；JevBench 公开层 0.935 vs Jev 的 0.866——但迁移整体（MMLU-Pro 与埋藏状态）Jev 仍以 0.800 领先 Jeeves 的 0.746，README 如实列出

**9/30 Show HN（84 分、37 条评论）：PSSA（plastic state-space architecture）逐 token 读写固定尺寸状态、维护一库可查询的"情景记忆"、并在前向传播中改写自身部分权重——全部用 Rust 手写，无 PyTorch/TensorFlow/任何 ML 框架。**

**关键细节：**
- 核心声称：同参数量、同语料下比 Transformer 学得更快，同一 CPU 上文本生成约快 12 倍；成本随序列长度线性增长（Transformer 每步都要重读全文、平方级开销）
- 为什么是 Rust（以及为什么这不是重点）：逐 token 权重更新、前向传播中写记忆库、给每个批量内核配标量参考路径——这些在自动微分框架里"每一步都在和框架打架"；梯度对照参考实现验证到约 3e-8。作者直言"架构才是主张，实现语言只是细节，欢迎 Python 移植"
- "plastic（可塑）"是题眼：绝大多数 LM 推理时权重冻结，PSSA 在推理过程中自我改写——接近教科书意义上的"学习发生在线"
- 定位：与 9/30 早报"浏览器里跑 7 个微型 LLM"、ESP32 集群同属"反数据中心"技术路线，但走得更远——不只是小，而是换了底层数学结构
