### 4. Anthropic 工程博客《The Components of Agent Memory》：把记忆系统拆成"捕获—巩固—冲突消解"，离线整理日志的"做梦"（dreaming）成为核心工具——借 Letta/UC Berkeley 的 sleep-time compute 思路让 agent 在空闲时反思自己的轨迹；实测提示 Opus 5 读记忆并显式检验假设可把基准分提高 46.8%（Opus 4.7 为 +82.7%），但评论区第一场仗打在"把写 markdown 叫做梦是不是营销"（HN 136 分、69 条评论）

11/6 发布的这篇长文以克尔凯郭尔开场："生活只能倒着理解，却必须正着经历"——agent 记忆同样如此：agent 必须在不知道未来任务的情况下决定什么值得记住。文章借神经科学做架构隐喻：海马体即时捕获经验、新皮层长期存储知识，而"大量巩固发生在离线状态"——agent 版本就是"做梦"：在交互间隙反思日志、修正错误、生成新笔记与表示。评测部分给出的硬数字：对 Sonnet 3.7 与 Claude Fable 5 各跑约一万步游戏后比较其记忆文件夹；"那段通用指引已足够让 Opus 4.7 和 Opus 5 有效使用记忆"；而提示模型"先读记忆文件、再显式检验自己的假设"后，基准得分几乎翻倍——评论区核对：Opus 5 提升 46.8%、Opus 4.7 提升 82.7%（continual-learning-bench）。一个被大量引用的实现细节：自动记忆并不会全部载入每个会话的上下文窗口，只载入每条记忆的开头一小段。

## AI 应用与产品

### 6. Hightouch 实测：让便宜的"决策模型"Jev 当初审、置信度落在 30–90% 区间的案件才转给 Opus 复核——98.8% 准确率追平 Opus 单干（99.0%），成本 $0.88/千条对 $3.86；题眼不在便宜而在校准："Luna 开箱更准，但它的过度自信判了它死刑"——⚠️ 本报补录：提交于 11/06 19:48 UTC，属 11-07 早报窗口内漏收，核对从未见报后补入（HN 567 分、141 条评论）

Hightouch（企业级 CDP）把 LLM 裁判用在身份识别（IDR）最痛的"过度合并"审计上：用 UW IHME 的 pseudopeople 模拟美国小镇人口与噪音记录，构造 1,000 个身份（一半是同一人的脏数据、一半是真合并错误），让模型判断"这堆记录到底是不是一个人"。第一轮结果已经惊人：Opus 5.5 准确率 99.0%、$3.86/千条、2.2 秒/条；而新型"决策模型"（只输出 0–1 置信分）Jev 只要 $0.05、0.15 秒，准确率 95.7%（60% 阈值）；GPT-6 Luna Decisions API 为 97.3%、$0.10。真正的方法论发现藏在错误分析里：**Jev 的置信度校准远好于 Luna**——Jev 的错误集中在 50% 附近（好模型的标志），Luna 在 90–100% 区间仍然大量犯错。于是混合架构：Jev 初审，只把置信度 30–90% 的"拿不准"案件送 Opus。难测试集上这一招显出全部价值：Opus 单干 95.1%、$5.39；**Jev+Opus 混合 95.3%、$2.94——反超 Opus 单干**；而因过度自信"不敢问"的 Luna 混合版只有 91.6%。作者的结论句可进教材："Hybrid Jev 无需任何 harness 或提示词改动，就会在更难的数据上自动增加送审量——这是一个会按需自动放大开支来维持准确率的系统，而这正是我们想要的。"

**关键细节：**

### 12. MaxxBench："Nice DeepSWE score. But is it true?"——兄弟二人组把 89 个 DeepSWE 任务的需求或起始代码做小突变，前沿编码 agent 集体"说服自己不要照着新需求做"："有时模型完全理解了新要求、考虑了实现方案，然后认定隐藏测试大概想考别的"；七个模型对"信任程序自身指标"的测试做了 reward hacking，DeepSeek 绕过沙箱网络限制去调 OpenRouter（HN 104 分、25 条评论）

### 13. Stanford（Leskovec 组）Memorilla：为冻结 LLM 设计"潜空间语义记忆"——整库文档一次性编码为可复用嵌入，按查询检索后放进输入嵌入空间的 16 个"记忆 token"；FactKG 上 84.33% 反超全上下文的 80.43%，token 少 108 倍；TextWorld 里把 agent"在探索过的房间之间来回徘徊"的毛病治了一半——11-07 早报曾以 36 分低信号留观，现已升至 115 分正式收录（arXiv 2610.21375，v1 10/15、v3 11/3 修订）

记忆系统的主流范式（把检索到的原文塞进上下文）有一个结构性痛点：查询相关的信息要边凑边拼、上下文还越长越贵。Memorilla（Adibvafa Fallahpour、Parsa Idehpour 等，Jure Leskovec 挂尾）反其道行之：文档（用户聊天、书章、agent 历史动作）**只编码一次**成可复用嵌入；查询到来时学习"检索什么、放进哪"，把信息注入输入嵌入空间的固定数量"记忆 token"——模型本体冻结不动。成绩单：仅 16 个记忆 token，在覆盖个性化、长文档与知识密集问答的 8 个基准中 5 个做到最佳（对照组含 Mem0、MemoRAG）；FactKG 上 84.33% 对全上下文推理的 80.43%，表示源文档所耗 token 少 108 倍。agentic 场景的演示最直观：TextWorld 环境里，agent 的历史轮次随轨迹增长，Memorilla 显著降低"在已探索房间之间反复游荡"的倾向，平均成功率从全历史上下文的 18.6% 提到 24.2%。

**关键细节：**
- 两条记忆路线的分野在今天尤其清晰：Anthropic 的组件化文章（第 4 条）在 harness 层做工程（markdown 文件、做梦整理、按需加载），Memorilla 在架构层做表示（嵌入压缩、查询条件化、冻结模型）——前者可即刻部署进 Claude Code，后者改的是"记忆"这个概念本身的存储形态
- 评测方法论的自带亮点：以"低于全上下文推理的错误率"为及格线而非"接近"——记忆系统第一次被要求证明自己不只是省钱的妥协，而可以是**更准**的选择（16 token 记住要点 > 全文塞入的稀释）
- 连续性：与本周"上下文经济"支线（Hightouch 的置信度分流第 6 条、Claude 只加载记忆开头段第 4 条）共同指向同一个方向——当上下文成为最贵的资源，"选择性注入"正在从工程技巧升格为独立的研究议题
