### 2. 🔥 汉堡安全公司审计 15.9 万个 Lovable 项目：护照号、20 万条私聊、28 万封客户邮件无需登录即可读取——"无技术背景"的开发者承诺与 Supabase 行级权限的默认陷阱叠加，vibe coding 平台第一次被平台级量化审计（HN 356 分、109 条评论）

Crissy Field GmbH（与 Handelsblatt 合作）实读：研究用 Common Crawl 数据集识别出 2025 年 12 月至 2026 年 9 月间的 159,041 个 Lovable 项目，其中 34,545 个使用 Supabase；24,664 个网站在首屏加载时就无登录下发数据库记录。研究者再用同一 API key 发起只读请求获取更多内容：7,403 个网站（30%）的 10,560 张表里检出含邮箱的记录。实锤案例：某德国生活方式论坛暴露 8 万+ 份完整档案（姓名/邮箱/生日/性别）与 20 万+ 条聊天记录；某服务商暴露 1,000+ 条含护照号、有效期、国籍的证件记录；另有活动票务与餐饮记录（电话、地址、支付信息、票码）、物业公司的内部邮件 AI 摘要（涉租户与业主）、28 万封客户邮件、数万份合同发票与 WhatsApp 内部通讯。

**关键细节：**
- 技术根因在 HN 被一句话讲透（dudus）：Lovable 用的是 Supabase Auth，浏览器经 JS 库直连数据库——必须在 RLS（行级安全策略）里逐表配置访问控制，而"不会编程也能建应用"的用户恰恰不具备判断这件事的能力
- 研究者的诚实边界值得同行学习：30% 不应被读作"确认泄露率"（邮箱可能是公开联系方式或测试数据）；样本来自 Common Crawl 不具总体代表性；只下载了部分数据集；不公布访问方法以免降低攻击成本
- 平台责任的结构性错位是报告的靶心：营销反复强调"无需技术知识"，条款却把应用与数据责任全部推给客户——自动化检查不能替代专业安全评估，处理真实客户数据前应做权限与账户隔离审查
- 放大效应写在模式里：Lovable 的数据库集成遵循可复用模式，"对一个应用有效的攻击路径，对其他应用几乎零成本复用"——攻击面从单点变成类别
- 连续性：本报 AI 代码质量/安全线第六拍——Humble Bundle vibecoding 安全事故（11-13 第 13 条）是单公司样本，本条给出第一次平台级测量：15.9 万个项目的横断面把"AI 生成应用的安全默认值"从轶事变成了统计问题

### 3. 🔥 意大利监管机构对 Meta 开出 8.05 亿欧元罚单（约 8.87 亿美元）：Facebook 安卓应用"照片推荐"功能未明确告知即获取约 2,000 万用户的相册访问权——60 天内须默认关闭并单独征得同意，Meta 称将上诉（HN 242 分、151 条评论）

## 模型与基础设施

### 4. NVIDIA 官方技术博客教你在两台 DGX Station 上跑 GLM-5.3：753B 参数 NVFP4 量化 MoE（464GB 权重）超出单卡 GB300 的 252GB 显存，ConnectX-8 RDMA + vLLM 张量并行拼出单一 OpenAI 兼容端点，SPEED-Bench 编码基准峰值 607.8 tok/s（HN 119 分、57 条评论）

NVIDIA 开发者博客（11/13，Fatima Fall）实读：GLM-5.3 NVFP4 是 Z.ai 混合专家模型的量化版——753B 总参数、每 token 激活 40B，稀疏激活省算力但全部权重须常驻显存（每个 token 可能路由到任意专家），约 464GB 的 checkpoint 超过单颗 GB300 的 252GB HBM3e。方案是两台 DGX Station 经 ConnectX-8 RDMA 互联、TP=2 各持有一半权重与计算，vLLM 启动跨机分布式服务，Station A 经单一 OpenAI 兼容 API 返回结果；启用多 token 预测（MTP）、FP8 KV cache 与前缀缓存。AIPerf 基准（SPEED-Bench Coding 数据集）：并发 16 时总输出吞吐峰值 607.8 tok/s，并发 32 降至 385.0 tok/s、平均请求延迟 453.5 秒。

**关键细节：**
- 博客页顶的"AI-Generated Summary"标注（Powered by NVIDIA Nemotron）本身就是个时代注脚：教人本地跑前沿模型的官方教程，摘要也是模型写的，末尾还带着"AI 生成内容可能总结不完整"的自我声明
- HN 的冷水来自成本端（AnotherGoodName）：这套 20 万美元级、每台 1.6kW 且风扇轰鸣的配置，并发 16 的 600 tok/s 远超家庭与小企业的真实需求——"真要别人告诉你 reconsider 吗？"
- meatmanek 的正面证词有分量：GLM-5.3 已是其日常主力（写代码、做调查、跨代码库修改、自己找文档），"足够聪明、够快、够便宜"；Keyframe 代表另一极——三大厂商的审查与"价值观输出"把用户推向自托管（他的方案是吃灰的 3090 + Strix Halo 395 的土法炼钢）
- 有趣的镜像：本报昨日第 3 条的权重取证报告里，GLM 新模型仍读作 Hopper 世代训练——而 NVIDIA 官方博客今天演示"用 GB300 工作站伺候 GLM"：中国开放模型的训练侧与美系硬件的推理侧在同一周各自成为新闻
- 连续性：本报本地推理线第五拍——Apple Harbor（11-12）→ ExecuTorch WebGPU（11-13）→ smolmaxxing（11-13）→ Edge0-145B（11-14）→ **双 DGX Station 工作站集群**：从 MacBook 到工作站，"前沿模型本地化"的谱系在一周内两头同时扩张

## AI 应用与产品

### 5. Anthropic 重设计 Claude Code Projects：从"文件夹"变成"会话"——你给目标与仓库，coordinator 拆解任务、并行分发 threads（每个 thread 是一个独立分支上的云端 Claude Code 会话）、审查合并；HN 帖内产品团队成员现场答疑（HN 97 分、31 条评论）

Anthropic 官方资源页实读：新 Projects 的定位句是"from folder to conversation"。启动一个项目时选定目标与 repo/上下文，Claude 先建议可立即着手的工作；在主对话里像给幕僚长下简报一样派活，coordinator 把工作路由到新建或已有的 threads——每个 thread 是一个跑在独立分支与仓库副本上的 Claude Code 云端会话，可再分裂 subagents/loops/workflows 加速；thread 间的代码重叠按普通 PR 的合并冲突处理。长任务设计：所有 thread 共享一份累积记忆（"记得发布改到了周五、export 功能为何被砍、动计费服务前该先问谁"），可从手机随时介入，人离线后继续跑。官方示例：把"降低结账 p75 延迟"设为目标，让 Claude 并行 profile 各端点、测试优化、开 PR；或连接 API/Web/移动三个 repo，让它逐仓迁移废弃端点的调用方并排出合并顺序。Beta 先开放给无存量 Web/桌面 Projects 的部分 Pro/Max 云端会话用户。

**关键细节：**
- HN 帖的团队内视角难得：bcherny（Boris，Projects 团队）解释动机——"随着模型变聪明、token 效率变高，人们自然开始并行跑更多 agent，Projects 就是把这种用法产品化"；russellbeattie 的批评指向层级（coordinator→worker→threads 的多层让 thread 难追踪，"试了一次就退回旧工作流"）
- enraged_camel 的需求代表重度用户心声：希望给 coordinator 单独指定推理档位——"我的 orchestrator 是全知全觉的 staff 工程师（Fable 跑 high/xhigh），workers 是干活的中高级工程师（Opus）"——多模型多档位编排已是事实上的工作流
- 时点说明：该资源页标注日期为 9 月 17 日（疑似此前灰度），11/14 的 HN 帖与团队答疑使 coordinator 模式进入大众视野，本报按文档内容与 HN 讨论口径收录

## 研究与突破

### 8. 600 次实验的 JEPA 世界模型独立复盘：LeCun 阵营的 LeWM 不用重训一行代码，仅靠"每 25 步给一个子目标"就把长程任务成功率从 22% 拉到 80%——换上完美物理引擎反而只 +20 分；"瓶颈不在预测器，在用法"（HN 284 分、48 条评论）

Haddy Alchaer 个人研究长文实读：JEPA（联合嵌入预测架构）主张在嵌入空间而非像素空间做预测——编码器把观测压成向量，预测器根据"当前嵌入+动作"预测下一帧嵌入，规划器在预测器里试演上百条动作序列挑最优。作者对 LeCun 团队今年发布的 LeWM（基准为 Push-T 推块任务）做了 600 次实验，第一个对照就颠覆直觉：在每 25 步提供专家子目标的条件下，把预测器换成模拟器的完美物理，长程成功率 77%，学会的预测器 78%——在训练分布内的路径上，LeWM 的预测已经"和物理一样好"。真正的杠杆在规划用法上：原版一次性规划 75 步成功率 22%，完美物理也只到 42%（+20）；把任务切成每 25 步一个子目标链接起来，同一个模型冲到 80%（+58）。全部四种新规划方法均无需重训；前两种合计把成功率推到 85%（约等于直接喂专家子目标）；后两种面向更难的目标分布，其中"只改目标评分方式"的单一改动带来 60 分提升——是换完美物理（+20）的三倍。

**关键细节：**
- 最有分量的质疑来自 robotresearcher：所谓"更难的测试"其目标帧仍取自专家演示——"为什么如此依赖演示分布来定义任务空间"，直指基准有效性的软肋；kooi（控制论背景）则把 JEPA 读作经典 M/P 模型的现代回声
- derefr 的观察很有味道："这个研究过程本身像是被 LLM 主导的——LLM 总是锚定输入里的示例、生成示例的变体"——AI 辅助研究的方法学第一次成为被审对象
- 数字的可复用性：78%≈77%（学习预测器 vs 完美物理）、22%→80%（子目标链接）、+60 分（目标评分改动）——三个数字合起来讲一个反共识故事：世界模型的短板可能不在"预测准不准"，而在"怎么用预测"
- 连续性：本报"生成式 vs 嵌入式世界模型"线的第一个大规模独立检验——此前本报报道的多为生成式路线；本条为 LeCun 的"像素是浪费"论点提供 600 次实验级弹药，也暴露其基准依赖演示分布的方法论软肋
