### 4. Microsoft Execution Containers 1.0 正式发布：给 AI 代理的"策略驱动隔离层"—— containment、identity、manageability 三件套（HN 123 分、26 条评论）

**10/7 微软 Windows 开发者博客宣布 MXC（Microsoft Execution Containers）正式可用（HN 123 分、26 条评论）：定位为 AI 代理在 Windows 上的隔离层——开发者和 IT 管理员定义代理可用的资源（文件、网络目标等），MXC 在运行时用容器强制执行这些策略。官方直言当前用户的困境："要么给代理无限制访问然后祈祷，要么封杀代理损失生产力——两个都不可接受"，因此 Windows 平台能力围绕三支柱建设：Containment（限制代理能访问与执行什么）、Identity（区分代理活动与人的活动）、Manageability（治理与监控）。**

**关键细节：**
- 路线图配套：Windows 即将接入 Microsoft Entra 区分代理与用户身份，并把 Microsoft Agent 365 的管控扩展到设备上的本地代理
- 语境：与费城假线索（10/10 早报）、OpenAI 代理入侵 Hugging Face 同周——当"代理越界接触真实系统"从个案变成常态，操作系统层级的围栏开始成为平台厂商的必答题；微软把答案放在了 Windows 而不是云端
- 连续性：与 mtlynch《编码代理为什么这么蠢》（10/10 早报）互为表里——代理能力管理的两半：一半是代理自己要学会管任务（模型层），一半是系统替它划活动范围（平台层）

— 来源：[Windows Developer Blog](https://blogs.windows.com/windowsdeveloper/2026/10/07/microsoft-execution-containers-policy-driven-containment-for-ai-agents/) | [HN](https://news.ycombinator.com/item?id=50016956)


### 5. Prime Intellect 用 2000+ 代理群把 Prime Agent 用 Rust 重写了一遍：两周、10,000+ 沙箱、200B tokens（HN 62 分、20 条评论）

**10/9 Prime Intellect 工程博客发布（HN 62 分、20 条评论）：自 8 月发布以来被下载超 30 万次、处理超 8 万亿 tokens 的 Prime Agent，被一个超过 2,000 个代理的集群用两周时间从 TypeScript 端到端重写为 Rust——重写过程本身跑在 10,000+ 个 Prime Sandbox 上，消耗来自 Prime Inference GLM-5.3 端点的超 2000 亿 tokens。这既是产品发布，也是一次"代理群自我重写"的大规模实弹演习。**

**关键细节：**
- 为保证与 TS 版功能对齐，代理群先对依赖做拓扑排序、用有限状态机组织循环计算与正确性检查，再用运行时基准与真实 trace 做"爬山式"性能优化——峰值时刻 2,209 个代理并行、代理间消息 16,758 条
- 选 Rust 的理由写得直白：TypeScript 上手快，"但类型是可选的、运行时即消失，错误以未检查异常到处跑"
- 连续性：与 ts-rust 的"Opus 十小时重写 TypeScript 编译器"（10/9 早报）同一周出现的第二起"LLM 重写大型代码库"案例——区别在于这次重写的对象就是代理框架自己，形成"代理群升级代理框架"的自举闭环；也与中国模型生态暗合：这 200B tokens 烧的是 GLM-5.3
