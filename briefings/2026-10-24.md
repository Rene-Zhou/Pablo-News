### 3. 🔥 Anthropic 与 Theorem：用 Claude 给 123 个开源库的汇编代码写形式化证明——"多年、数万亿次测试都没发现"的老 bug 顺带出土，官方称这是首个 AI 大规模汇编级形式化验证（HN 436 分、53 条评论）

**Anthropic（10/22，Frontier Red Team 团队，与 Theorem 合作）：《LLM 正让形式化软件验证在更大规模上变得可行》。用 Claude 在 100+ 个真实开源库（页面副标题口径 123 个）的汇编代码层（RISC-V）证明安全属性——据其所知，这是首个把 AI 形式化验证用于生产软件汇编层的大规模工程。写作证明的过程中，Claude 还发现了"逃避检测多年、尽管经受过数万亿次测试运行"的 bug。背景陈述直指本周：Linux 内核近期披露超 1000 个漏洞，前沿模型越来越擅长"把看似无害的 bug 串成关键 exploit"，传统防御已不敷使用——需要能证明代码无 bug 的方法，而形式化验证历史上需要数年的专家投入，"现在不再如此"。**

**关键细节：**
- 方法即卖点：把代码翻译为数学模型、证明其始终遵守安全规则；证不出来就意味着可能有 bug，失败的性质还暗示 bug 在哪——"每次消除失败原因后重复这个过程，最终得到'代码不存在违反规则的 bug'的证明"
- 官方坦承的局限（HN jaykru 转引附录）："agent 写的证明与任何其他证明一样'好'——它们证明了等价定理。但 agent 能否把这种冗长的证明风格直接扩展到更复杂的程序，仍有待观察；MachCSL 等 agent 验证项目的经验暗示答案可能是否定的——agent 会撞上冗长性导致的复杂性墙"
- HN 的追问集中在"证明什么"：mjorgers——"要证明一个命题，命题必须正确建模代码的现实。那你如何确信自己验证的是你真正的程序，而不是证明了另一个东西？"；woggy——"即便有 LLM，确保形式化规范真正覆盖你想要的东西依然很难：你怎么知道 LLM 证明的是你想要的？"；paxy 的总结最锋利："这一切只会把问题上移一层——软件本质上是对人类期望的一种表示，你怎么形式化验证人类的期望？"
- pinevale 的质疑带刺："形式化验证，对着什么验证？那个覆盖所有预期与非预期输入、所有利益相关者、所有用户行为的 100% 形式化规范？在 vibecoding 时代？"——lenerdenator 则从使用侧附和："Claude 日常工作里明明能很快写脚本形式化验证系统状态，却从不主动这么做"
- 也有建设性支线：UncleEntity 分享了自己的 JavaCard VM 做法——让 Claude 分别从规范实现 VM 和证明生成器，"两边得存在同一个 bug 才能漏网"，配合 ESBMC 静态验证已经抓到过几个 bug
- 连续性：与 10/22 的"用 Claude 缩减代码攻击面"（不找单个漏洞、砍掉不可达代码）同属一条研究线，如今升级到"证明剩余代码满足安全属性"；放在 PHP2Shell→iPhone 的一周里读，这是防御端给出的对偶答案——攻击端在用 LLM 把理论漏洞变成 exploit，防御端在用 LLM 把"证明无洞"从数年专家工程变成可规模化的流水线

### 5. OpenSSL 4.1.0 发布：DTLS 1.3 首次落地、GREASE、IKEv2 KDF——ML-DSA/ML-KEM 后量子算法的 NTT 与 AVX-512 优化同版齐发（HN 172 分、53 条评论）

**OpenSSL 10/23 发布 4.1.0 功能版（距 4.0 线的又一次大版本更新，master 上已有 440 个提交领先）：新增 DTLS 1.3 支持（RFC 9147，配 ossl-guide-dtlsv13(7) 手册）、RFC 8701 GREASE、SSL listener API 的 DTLS 支持、IKEv2 KDF，以及 Elbrus2000（e2k）架构的初始支持。性能侧的重点全在后量子：ML-DSA 与 ML-KEM 的 NTT 操作在 ppc64le 上优化、ML-DSA 在 x86_64 上优化、ML-DSA 的 SHAKE x4 获得 AVX-512 实现、AES-CBC 解密拿到 AVX-512 与 VAES 优化。**

**关键细节：**
- 同版也有清理：移除 Windows-on-Itanium（VC-WIN64I）与 Windows CE（VC-CE）构建目标；删掉名不副实的 `no-ecdsa`/`no-ecdh` 配置项（它们从未真正禁用实现，现在用 `no-ec`）；`tsget` 工具从被弃用的 WWW::Curl::Easy 迁到 Net::Curl::Easy
- 官方在发布说明里罕见地列了四条 DTLS 已知问题（KeyUpdate 丢弃重传缓冲、listener 永久接收失败被报成 WANT_READ 等），修复排入后续版本——新特性的成熟度一目了然
- 连续性：后量子算法（ML-DSA 签名/ML-KEM 密钥封装，即 FIPS 204/203）从"标准文本"走进全世界部署最广的 TLS 库的性能优化清单；放在 eMudhra 退出证书业务（10/23 头条）的同一周看，Web PKI 信任层在塌方、而底层密码库在为后量子时代铺轨——一破一立同框
