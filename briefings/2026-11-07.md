### 1. 🔥 Claude Code 被曝把登录邮箱写进 User-Agent 发给任意第三方网站——受害者"每天收到几十封精准诈骗邮件"，GitHub issue 标题即定性"Privacy violation"；Anthropic 官方现身致歉：根因是为治 @author 幻觉把账户邮箱塞进了模型上下文，"下周早些时候的版本将移除"（HN 1527 分、479 条评论）

motoroco 11/5 提交的 claude-code issue #107757《Bug Report: Privacy violation in User-Agent header》（现 95 条评论、仍处 Open）："我每天收到几十封诈骗邮件，因为 Claude Code 在未经我允许的情况下、在做网页搜索时把我的邮箱通过 User-Agent 请求头泄露给了任意第三方。"他的诉求超越了 opt-out："这不该是一个可以开关的设置，它需要从 harness 里被彻底移除——它对任何一方都没有好处"，并宣布把公司迁移到 Pi + OpenRouter。HN 讨论把机制拆开：Claude Code 会把登录账户的邮箱放进模型上下文，当模型自己写 curl 命令做网络请求时，有时会把邮箱填进 User-Agent 头。

**关键细节：**
- lydia_hallie（Anthropic，Claude Code 团队）的官方回应："我们正在把账户邮箱从 Claude Code 提供给模型的上下文中移除，下周早些时候的版本生效，届时我会回这个帖子更新。很抱歉让这件事发生。"——她给出的根因链：用户曾报告模型会给 @author 标签之类的东西幻觉出人名（因为缺少账户信息），于是团队给已登录用户把账户邮箱加进了上下文；但当 Claude 自己写命令（如 curl）时，偶尔会把邮箱放进 User-Agent
- varenc 的考古获高赞：很多人是在调 SEC API 时观察到这个行为——SEC 公开数据 API 的文档要求 User-Agent 里带联系方式、否则直接拒绝（他贴出 curl 对照：默认 UA 被拒、带邮箱成功）——"模型在替用户遵守 API 礼仪"与"向第三方泄露身份"在此是同一件事
- mk89 的受害者自述："这解释了我换到 Claude 之后工作邮箱收到的大量诈骗邮件……它们甚至带我的全名，不只是'dear customer'。蠢的是我还以为公司数据库被黑了"
- grey-area 的三连问被顶起：Claude 该不该拿到用户细节（不该，除非手动输入对话）？该不该碰沙箱项目文件之外的任何东西（不该）？该不该在没有完整请求日志的情况下上网（不该）——"桌面 UI 给人的印象是 LLM 只能碰显式加进项目的东西，而这个印象是不准确的"
- agentdev001 盘点"前科清单"：#55743（5 月：Max 账户邮箱无 opt-out 注入上下文）、#72518（6 月："Anthropic 在 Claude Code 里嵌了 spyware"）等——"这不是孤例"
- 连续性：与 Postman 静默装 AI 插件（11-04 第 2 条）、Codex 训练开关静默重置（11-04 第 12 条）、Gemini 训练订阅用户聊天（11-05 第 3 条）同属本周"工具默认行为 vs 用户知情"主线——agentic 工具的每一个默认值都在变成隐私边界，而这一次是 Anthropic 在 1527 分的聚光灯下亲自演示
