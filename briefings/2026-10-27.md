### 2. 🔥 OpenAI 发布 GPT-6.1 Terra：主打"规模化计算机使用"——Agents' Last Exam 中等推理档较 5.6 Terra 提分 15 个百分点、成本仅三分之一，与 GPT-6 Astra 打平但每 token 价格只有十分之一；标准 API 价格比 5.6 Terra 与 6.1 Sol 低 50%（HN 331 分、189 条评论）

**OpenAI 官方页面：GPT-6.1 Terra 是"快速、高效的模型"，把精细视觉推理与精确计算机使用（computer use）结合，写作业余的日常事务——起草提案、解读技术图纸、填表、剪视频。"它在我们的模型家族中继续推进成本-智能前沿：标准 API 价格比 GPT-5.6 Terra 和 GPT-6.1 Sol 低 50%，让开发者可以负担高体量自动化——比如读取进项发票并把明细录入会计软件。"在 ChatGPT Work 与 Codex 里，同样的用量额度能覆盖比 5.6 Terra 更多、比 6.1 Sol 与 GPT-6 Astra 大幅更多的任务。**

### 10. Drew Breunig 的"上下文工程现状"演讲：从 2024 年底"RAG 已死"的百万 token 幻梦讲起——"长上下文不是万灵药"；四种失效模式（污染、分心、混淆……）才是日常；工作定义是"知道什么时候该确定性、什么时候该概率性"，O'Reilly《上下文工程手册》在路上（HN 247 分、63 条评论）

**Drew Breunig（dbreunig.com，10/24）：本周在 AGNTCon 所做演讲《Context Fails & Fixes》的幻灯与整理稿——一篇事实上的"上下文工程现状"。回望 2024 年底："那是'RAG 已死'论的高峰——只要上下文窗口够大，把整个互联网塞进去，不用做检索、不用建 agent、AI 就被解决了。"模型厂于是从 12.8 万 token 冲向百万 token（Gemini 1.5 起），Llama 4 Scout 更以 1000 万 token 抢跑——"但它不太是我们希望的东西，推理是个问题，Scout 没真正流行，我们也再没等来下一块 Llama"。但百万 token 拿到了，"于是有了更多空间装下更多问题：长上下文不是万灵药"。**

**关键细节：**
- 失效模式清单（演讲核心）：上下文污染（poisoning）——不该进上下文的东西进来了（幻觉或坏事实），模型过不去了；上下文分心（distraction）——上下文长到模型开始"盯着上下文"压过基础知识；上下文混淆（confusion）——无关事实进来并以我们不完全理解的方式影响模型，"这一条特别隐蔽：模型会假设你是谁"
- HN 评论区把演讲拉回日常：jdw64——"这就是我现在反复给的建议。有人说'我的编码 agent 行为很怪，Claude 被削弱了'，我问'你的上下文多大？'"；但 jdw64 自己补了另一头："信息太少同样出怪行为——多数 agent 反模式在中等上下文下工作良好，过多或过少都不行"
- 工程派的最深一问在压缩与缓存的交界（agentdev001 提出、CBLT 总结算账）："用便宜决策模型在压缩前剪枝？你为了省'把数据装进生成模型上下文'的钱，先付了'把同样数据装进决策模型上下文'的钱——而且剪掉中间某轮会让后面所有轮的 KV cache 失效。只有'需要更聪明的模型做压缩却付不起它读全部上下文'时才划算，那是真正的窄门"
- 连续性：本报 harness 主线（Corgi 10/25、GVS5H 与 Thinkrail 10/26）从工具与编排侧转到上下文侧；与 10/26 danluu"模型能有效验证的范围与能实现的范围之间的缺口一直在拉大"同题——上下文工程正是那条缺口的日常名字

**布朗大学新闻（10/26）：本科高年级学生 Cunyan Ma（与该校技术责任、重塑与再设计中心 CNTR 合作）发布可交互地图，把技术公司及其中介与全球数据工人连接起来——聚合既有数据工人数据库、自采数据与新闻报道。作者的动机陈述："我主要的动机，是把'AI 殖民主义'这个观念以有冲击力、立刻可及的方式可视化。我想填补的空白是：我们对数据工人的了解大多来自记者与作者的事故式报道——那些很好，给了我们工酬与条件的细节；但我想开始拼出'AI 殖民主义'整体上长什么样。"**
