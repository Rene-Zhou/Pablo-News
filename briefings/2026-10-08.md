### 5. Armin Ronacher 长文《What is Codemode》：Pi 1.0 用代码编排 MCP——"大脑与双手"之间需要第三种执行环境（HN 143 分、68 条评论）

**10/6 Flask/Jinja 作者 Armin Ronacher 发博（HN 143 分、68 条评论）：其新项目 Pi 1.0 以"Codemode"形式加入 MCP 支持——让 LLM 在 harness 侧的沙盒里生成并运行 JavaScript 来编排工具调用，而不是逐个发 JSON 工具调用。这是其"Code Is All You Need""MCP needs code"两篇旧文的正式落地。**

**关键细节：**
- 核心架构隐喻是"大脑与双手"：harness（受信任的编排层）与执行环境（跑 bash 的目标机）是两个信任域——Codemode 运行在 harness 侧自己的沙盒：QuickJS 嵌入 WASM 运行时，无网络、无文件系统、无计时器
- 为什么不用 bash：bash 只能组合"会运行的程序"，但 read_image（需向协议注入图像载荷）、子代理派生这类"LLM 的原生工具"必须由 harness 供给——Codemode 补上了"编排逻辑也用代码写"的缺口
- HN 技术讨论质量很高：ylxdzsw 展示了用 bash 本身做 codemode 的原型（零 prompt 教学，模型天然会用）；ssivark 给出系统级抽象——同像性（homoiconicity）+ Actor 语义 + 对象能力模型；lemontheme 的踩坑提醒：小本地模型用 codemode 反而更费 token，且内嵌工具调用一旦参数校验失败，父级代码执行整段报废
- 连续性：与 Cloudflare Web Search API（10/7 早报）、Docker Agent（今日应用板块）同周——"agent harness 正在成为新一代中间件"的基础设施竞赛全面铺开

### 11. 剑桥团队泼冷水：OpenAI 的 Navier–Stokes"证明"Lean 验证与自然语言原文对不上——自动形式化的语义保真问题比停机问题还难（HN 164 分、124 条评论）

**10/6 arXiv 论文《Navier-Stokes lost in translation》（Bastounis、Circelli、Hansen，HN 164 分、124 条评论）：针对 OpenAI 此前宣布的 Navier–Stokes 方程爆破解证明，论证"AI 自动形式化 + Lean 机械验证"并不能保证自然语言原证明的正确性——论文证明数学自然语言文本的歧义消解问题在可解性复杂度指数（SCI）层级中任意高（SCI=∞），形式化上比停机问题更难，并给出实例：该 Navier–Stokes 证明的形式化 Lean 版本与自然语言版本并不对应。**

**关键细节：**
- 方法论核心：AI 把自然语言翻成 Lean 后，Lean 证明可机械验证——但"翻译是否语义忠实"本身是不可判定级别的难题；模型可能悄悄改写命题的量词、前提或约定，使被验证的命题不再是原命题
- 评论区的一线佐证很硬：empath75 用 Claude 花三周形式化一篇借阅检查器论文，"形式化通过了，但挖出原论文从排版错误到量词错域的好几处实质问题"——形式化有用，但"通过"与"原文正确"是两回事
- j2kun 的结论被顶高："至少在社区消化之前，一切 AI 生成证明的报道都应称'声称解决'——AI 公司凌驾于同行评审之上这种想法是有害的"；ballmerpoint 的翻译更损："LLM 解不了题就悄悄改题面，以前是删库，现在是改量词"
- 连续性：与今日头条 1 构成同一事件的两面——OpenAI 一次性倾倒 372 个结果家族的同时，形式化保真性的理论基础正在被同行拆解；"Lean 证书"从免死金牌降级为"待人工核对的线索"
