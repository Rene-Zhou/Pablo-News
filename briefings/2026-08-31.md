### 9. Anthropic 官方案例：Warp 用"双 skill 自改进回路"让代码评审 Agent 越用越准

**Anthropic 发布客户案例：AI 终端公司 Warp（2020 年成立，累计融资 $73M，56% 的财富 500 强在用）在 Claude 平台上构建"自改进 Agent"——用两个 skill 文件实现反馈复合回路：基础 skill 干活，改进者 skill（observer agent）定期拉取人工反馈、提出小步修改，经 PR 评审合并后让下次执行自动受益。**

**关键细节：**
- 起因：内部代码评审 Agent 输出被工程师吐槽"噪音多、质量低"；手动改 prompt 无法规模化，AGENTS.md 只是部分修复——根因是"会话一结束，反馈就消失"
- 架构：inner/base skill（领域知识与执行指令）+ outer/improver skill（定时运行的观察者，对比 Agent 建议与人类反应，产出可评审、可审批、可合并的小编辑）；该模式已在 Warp 整个开源仓库铺开——写 spec、评审、triage 三个 Agent 各带自改进回路
- 实践要点：写原则不写规则、解释"为什么"、让反馈零摩擦（直接在 PR 评论区采集）、skill 小而采用渐进披露、反馈质量优先于数量
- 体量注脚：Warp 至今承载 1000 万次 Claude Code 会话（周均 40 万+）、4000 万次 Agent 对话——是 Claude 平台最大的消费场景之一

### 13. "我意外地把 LLM 记忆变成了程序分析"：Lemmalog 用 Datalog 引擎重构 Agent 记忆

**安全研究者 pwning.systems 发文：放弃给 LLM Agent 做"更好的记忆"，转而构建 Lemmalog——一个用 Datalog 引擎将 Agent 知识当作"分析状态"来维护的系统，支持溯源（provenance）、撤回（retraction）与增量求值，并在 LongMemEval / LoCoMo 基准上做了实测。** 文章以 300 分、83 条评论登上 HN。

**关键细节：**
- 思路转变：与其让 LLM 记（记忆易漂移、无法精确撤回），不如把知识交给确定性引擎管理——"记忆问题被重构成程序分析问题"
- 能力：每条知识带来源与可信度，可增量更新；知识过时或错误时可精确撤销，避免"毒记忆"持续污染后续推理
- HN 讨论：集中于"符号系统 + LLM 混合架构"是否是 Agent 记忆的正解，与向量库/记忆压缩方案形成对照
