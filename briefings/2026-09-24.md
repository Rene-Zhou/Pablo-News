### 1. 🔥 Anthropic 生命科学实验室首批成果：Claude 自主发现类 CRISPR 重复序列的新酶系统 ART

**9/23 Anthropic 宣布成立生命科学研究组与实验室，并公布首批成果（232 分、227 条评论登顶 HN）：Claude 代理在科学家只给高层方向的情况下，自主发现了一个与 DNA 重复序列阵列相关的新酶系统——布局与 CRISPR 类似、功能未知，命名为 ART。** 团队 2026 年春组建，目标是"用 Claude 做基础生物学研究"：探索 DNA 数据集寻找未表征蛋白家族、大规模生成假设、在实验室里验证。

**关键细节：**
- 发现路径：Claude 代理收集了 20 万+ 个逆转录酶（RT），筛出 3,500 个新候选系统，再浓缩为 20 个最有说服力的候选并生成人类可读报告——这类分析对人类专家需要数周到数月
- 现场感：Claude 在逐段读取 RT 旁边的原始 DNA 时惊呼"[旁边的 DNA] 令人惊叹：我能用肉眼看到串联重复阵列……这是类 CRISPR 的……重复阵列？！"随后像人类科学家一样计数重复、测量间距、比对已知 RT 系统、检索文献，确认后提交人类审查
- 系统构成：ART 主要存在于噬菌体中，三部分——RT、紧邻的伙伴基因、一组等间距 DNA 重复序列；首个实验显示 ART 阵列表达为一组不同的短 RNA，提示可能具有与 CRISPR 类似的可编程性
- 行业背书：CRISPR 基因编辑先驱、MIT/Broad 研究所张锋（Feng Zhang）审阅预印本后称"这是 AI 代理贡献于生物学发现的激动人心的例子，RNA 重复阵列与逆转录酶的关联确实引人入胜、值得深入研究"
- 方法论：全部工作在 Claude Science 与 Claude Code（任何科学家都可用的工具）中完成，外加自研 harness 协调多个并行 Claude 会话；因假设产出太 prolific，"假设本身成了研究对象"——团队研究"值得测试的提案有何特征"，反哺给 Claude 的指令

### 2. 🔥 DrivingBench：让前沿模型真开一台丰田——GPT-6 Astra 完赛锥桶赛道，Fable 5.1 最好 45%

**9/23 DrivingBench 上线（239 分、209 条评论登上 HN）：给前沿 LLM 一台真实丰田卡罗拉的方向盘、油门与刹车（comma four 设备接 CAN 总线），在固定锥桶赛道上逐条指令行驶、人类监督员随时备刹——GPT-6 Astra 成为唯一完赛模型（5 分 22 秒），Claude Fable 5.1 三次尝试全部 DNF（最好 45%），Grok 4.6 止步 11%，GPT-5.6 Sol 只有 6%。**

**关键细节：**
- 架构：手机热点串联笔记本（Codex/Claude Code/Cursor 聊天端 + MCP 服务器 + 网关）与 comma four（两路道路摄像头 + openpilot + 自研控制器，CAN 100Hz）；蜂窝延迟约 0.3 秒、Wi-Fi 约 0.05 秒，模型思考 2-30 秒，人类刹车间谍随时待命
- 成绩单：Astra（Codex medium）第 1 次尝试 49% DNF（8 条指令、$2.01），第 2 次同一会话内 100% 完赛（24 条指令、660 万 token、$7.74）——体现同上下文内的"上手学习"；Fable 5.1（Claude Code medium）最好一次 45%（$1.64）、三次均未完赛
- 作者：Aditya Ramabadran、Simon Mahns、Tobias Gessler（同等贡献）；明确声明与 comma.ai/openpilot/丰田及被测各模型厂商均无关联，公开视频与帧已为人脸模糊
- 定位：不同于机器人抓放演示或模拟器驾驶——感知、规划、控制、延迟层层叠加的真实世界评测；服务延迟低、吞吐高的模型天然占优（更快的思考与世界反馈回路）；v2 计划改进评测协议

### 3. 🔥 Claude Code 的 AGENTS.md 只有开着遥测才读：本地文件加载竟挂在远程特性开关上

**9/23 工程师 Przemek（blog.szypowi.cz）的实测博文登上 HN（416 分、235 条评论，为当日讨论最热的工具话题）：Claude Code 2.1.277 宣布支持 AGENTS.md（项目无 CLAUDE.md 时读取之），但加载器是内置插件 agents-md——isOnByDefault 为 false、可用性取决于远程特性开关 tengu_agents_md_mod；关闭遥测或非必要流量后，本地 AGENTS.md 会被静默跳过、无任何警告。** HN 标题随后被更新为 [fixed]。

**关键细节：**
- 实测方法：空目录放一个含 canary 词（PERIWINKLE）的 AGENTS.md，用 `claude -p` 询问——CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 或 DISABLE_TELEMETRY=1 任一变量都会让文件永不加载；设为 0 也无效（任何值都算开启阻断）
- 波及面：项目 .claude/settings.json 里的 env 块清空变量同样无效，无法按单个仓库开启；第三方网关、Bedrock 与 Vertex 一致中招（开关在那里无法解析为 true）
- 核心批评："从工作目录读一个 markdown 文件完全不需要网络，这里却要等服务端开关"——隐私优先用户的功能被静默降级，且每个会话都要先跑一趟取开关
- 变通方案：一行 CLAUDE.md 写 `@AGENTS.md`（@path 导入不依赖开关）
- 后续：HN 讨论中有人给出 Anthropic 方面的解释——这是临时的灰度发布设置、"完全的人为决策，与 AI 补丁无关"；也有评论认为"新特性先挂特性开关灰度、靠遥测判断健康度"是行业常规，但把本地文件 IO 与遥测耦合仍值得批评

— 来源：[blog.szypowi.cz](https://blog.szypowi.cz/p/claude-code-reads-agents.md-only-when-telemetry-is-on/) | [HN](https://news.ycombinator.com/item?id=49814947)

### 11. Scientific American 质疑：OpenAI 解的是"错误的 Navier-Stokes 问题"吗？——loophole 永远关不上

**9/21 Scientific American 发表分析（115 分、67 条评论登上 HN）：OpenAI 两周前宣布的 Navier-Stokes 解"看似有资格拿 Clay 研究所的 100 万美元奖金——但只用了一个有争议的 loophole"：其证明依赖一个含外力（external force）的变体，多数专家认为该变体与现实脱节、因此不那么有趣。**

**关键细节：**
- 专家态度：芝加哥大学 Luis Silvestre——"最重要的问题仍未解决。Clay 问题算解决了，但 Navier-Stokes 方程的核心问题没有"；模型的证明在某种意义上"找到并利用了问题表述中的漏洞"
- 致命跟进：上周四（9/17）三位数学家张贴证明——OpenAI 的方法永远无法扩展到解决完整问题；除非出现全新思路，这个 loophole 关不上
- 背景注：方程中的外力项（如重力）是可选项——现实中的流体都受外力，但专家心中"更纯粹、更根本"的问题是不含外力的版本
- 连续性：延续 9/22 早报"OpenAI 数学咨询组"故事——咨询组成立后的第一场技术性质疑已经到来

— 来源：[Scientific American](https://www.scientificamerican.com/article/did-openai-solve-the-wrong-navier-stokes-problem/) | [HN](https://news.ycombinator.com/item?id=49795260)

### 12. SlopShape：仅凭结构特征识别 AI 生成网页内容——98 macro-F1、改写也躲不掉、79% 能认出是哪家模型写的

**9/22 Show HN（63 分、21 条评论）：Sitefire（YC W26）团队发布 arXiv 论文 SlopShape——把 StoryScope（AI 生成小说的结构签名）复制到商业内容上：268 个公司域名的 2,250 篇 ChatGPT 前人类博客，对阵 5 个前沿模型生成的 11,250 篇 AI 镜像文章。**

- 结果：214 特征工具（其中 187 个结构特征、由 LLM 施测）在留出公司上达 98.0 macro-F1；把每篇 AI 文章用其生成模型自行改写后仍达 98.1——对改写鲁棒
